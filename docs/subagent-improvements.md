# Subagent System Improvement Analysis Report (서브에이전트 시스템 개선사항 분석 보고서)

## 1. 개요 (Overview)
`jeo-code`의 서브에이전트(Subagent) 시스템은 `gjc`의 역할 기반 에이전트(Role-agent) 철학을 계승하여 설계되었습니다. 본 보고서는 현재 구현된 서브에이전트 시스템의 구조와 동작 방식을 분석하고, 향후 시스템의 안정성, 성능, 사용성을 극대화하기 위한 구체적인 개선사항을 제시합니다.

---

## 2. 현재 아키텍처 및 구현 현황 (Current Architecture & Implementation)

### A. 역할 레지스트리 (`src/agent/subagents.ts`)
* **역할 정의**: `executor`(변이 가능), `planner`(읽기 전용), `architect`(읽기 전용), `critic`(읽기 전용)의 4가지 번들 역할을 제공합니다.
* **동적 확장**: `config.subagents` 설정을 통해 사용자가 커스텀 역할을 선언할 수 있으며, 기본적으로 읽기 전용(`readOnly: true`) 안전 장치가 적용됩니다.
* **능력 경계 (Capability Boundaries)**:
  * 읽기 전용 역할은 `write`, `edit`, `bash`, `mkdir`, `delete` 도구가 물리적으로 제거된 도구 세트(`subagentToolset`)를 부여받아 저장소 변경이 원천 차단됩니다.
  * 변이 가능 역할(`executor` 등)은 `bashAllowedPrefixes` 설정을 통해 실행 가능한 쉘 명령어를 화이트리스트 기반으로 제한할 수 있습니다.
* **완료 계약 검증 (`validateSubagentDoneReason`)**:
  * 각 역할은 완료 시 `done.reason`에 필수 마커(예: `Summary:`, `Changed Files:`, `Verification:`)를 포함해야 하며, 단순히 라벨만 적어두는 꼼수를 방지하기 위해 각 섹션이 실제 내용(non-whitespace content)을 포함하고 있는지 검증합니다.

### B. 동기식/비동기식 실행 제어 (`src/agent/task-tool.ts` & `src/agent/subagent-registry.ts`)
* **동기식 실행 (`task` 도구)**:
  * 부모 에이전트가 서브에이전트의 완료를 대기(block)하며 결과를 직접 수신합니다.
  * **병렬화 정책**: 읽기 전용 역할의 fan-out(`tasks` 배열)은 최대 4개(`MAX_FANOUT`)까지 병렬로 실행됩니다. 반면, 변이 가능 역할(`executor`)은 파일 경합(race condition)을 방지하기 위해 항상 직렬(serialized, concurrency 1)로 실행되며 최대 6개(`MAX_SERIAL_EXECUTOR`)로 제한됩니다.
  * **조정(Steering) 허브**: 병렬 실행 중인 서브에이전트들이 부모의 실시간 피드백(steering query)을 중복 소비하지 않고 각각 정확히 한 번씩 수신할 수 있도록 커서 기반의 브로드캐스트 허브(`createSteerHub`)가 구현되어 있습니다.
* **비동기식 실행 (Detached Subagents, `#9`)**:
  * `task {detached: true}` 호출 시 백그라운드에서 실행을 시작하고 즉시 제어권을 부모에게 반환합니다.
  * 부모 에이전트는 `subagent` 도구(`list`, `inspect`, `await`, `cancel`)를 통해 백그라운드 작업의 상태를 모니터링하고 결과를 수집합니다.
  * **생명주기 바인딩**: 턴(turn)이 종료되거나 Ctrl-C 발생 시 `cancelAll()`을 호출하여 백그라운드 프로미스 누수를 방지합니다.

### C. 부모 측 변이 감사 (Parent Audit, `cycle 18`)
* 서브에이전트가 완료 계약 마커를 허위로 작성하여 성공을 보고하는 것을 방지하기 위해, 부모 에이전트가 서브에이전트의 실제 도구 호출 이력(성공한 `write`/`edit`/`mkdir`/`delete`/`bash`)을 실측 카운트합니다.
* 변이 역할이 단 한 건의 파일 변경도 없이 완료를 보고하면 `[parent audit] ... UNVERIFIED` 경고를 첨부하여 신뢰성을 검증합니다.

## 3. 개선사항 분석 및 제안 (Proposed Improvements)

### 개선안 1: 비동기 서브에이전트(Detached Subagents)의 실시간 상태 모니터링 강화
* **현황**: 현재 비동기 서브에이전트는 백그라운드에서 실행되며, 부모 에이전트가 `subagent {action: "list"|"inspect"}`를 수동으로 호출해야만 상태를 확인할 수 있습니다.
* **제안**: TUI의 HUD 또는 상태 표시줄에 현재 실행 중인 백그라운드 서브에이전트의 개수와 간략한 상태(예: `[BG: exec-1(step 3/15), plan-1(done)]`)를 실시간으로 렌더링하는 컴포넌트를 추가합니다.
* **기대 효과**: 사용자가 백그라운드 작업의 진행 상황을 직관적으로 파악할 수 있어 멀티태스킹 경험이 크게 향상됩니다.

### 개선안 2: 비동기 서브에이전트의 결과 캐싱 및 영속화 (Persistence)
* **현황**: 현재 `SubagentRegistry`는 인메모리(`Map`)로 관리되며, 턴(turn)이 종료되면 `cancelAll()`과 함께 모든 기록이 소멸합니다.
* **제안**: 비동기 서브에이전트의 실행 이력과 최종 리포트를 `.jeo/subagents/` 디렉토리에 JSON 파일로 영속화합니다. 턴이 바뀌거나 에이전트가 재시작되어도 이전 턴의 백그라운드 작업 결과를 조회할 수 있도록 지원합니다.
* **기대 효과**: 장시간 실행되는 백그라운드 작업의 안정성이 확보되며, 세션 간 컨텍스트 추적이 용이해집니다.

### 개선안 3: 병렬 실행 시 파일 잠금(File Locking) 메커니즘 도입
* **현황**: 현재 변이 가능 역할(`executor`)은 파일 경합을 피하기 위해 무조건 직렬로 실행됩니다. 이로 인해 서로 다른 파일을 수정하는 독립적인 태스크들도 병렬로 실행되지 못하고 대기해야 합니다.
* **제안**: 태스크가 수정하려는 대상 파일 경로를 사전에 분석하거나, 실행 중에 락을 획득하는 파일 수준 잠금(Fine-grained File Locking) 메커니즘을 도입합니다. 서로 다른 파일을 수정하는 태스크는 병렬 실행을 허용하고, 동일한 파일이나 디렉토리를 수정할 때만 직렬화합니다.
* **기대 효과**: 변이 작업의 안전성을 유지하면서도 병렬 처리 속도를 극대화할 수 있습니다.

### 개선안 4: 완료 계약 검증의 시맨틱(Semantic) 강화
* **현황**: 현재 `validateSubagentDoneReason`은 단순 문자열 매칭 및 섹션 간 텍스트 길이 검증에 의존합니다. 이로 인해 무의미한 텍스트(예: "Summary: asdf asdf")로 채워진 리포트도 통과할 수 있습니다.
* **제안**: 완료 계약 검증 시, LLM 또는 경량 규칙 엔진을 활용하여 각 섹션의 내용이 실제로 유의미한 정보를 담고 있는지(예: 변경된 파일 목록이 실제 파일명 형식인지, 검증 단계가 구체적인 명령어인지) 검사하는 시맨틱 가드를 추가합니다.
* **기대 효과**: 서브에이전트 리포트의 품질을 보장하고, 부모 에이전트가 잘못된 정보를 바탕으로 의사결정을 내리는 위험을 줄입니다.

### 개선안 5: 비동기 서브에이전트에 대한 조정(Steering) 지원
* **현황**: 현재 비동기 서브에이전트는 부모의 실시간 조정(steering) 메시지를 수신하지 못합니다.
* **제안**: `SubagentRegistry`에 메시지 큐를 추가하여, 부모 에이전트가 `subagent {action: "steer", id: "executor-1", message: "..."}`와 같은 형태로 실행 중인 백그라운드 서브에이전트에게 실시간 지시사항을 전달할 수 있도록 개선합니다.
* **기대 효과**: 백그라운드에서 잘못된 방향으로 실행 중인 서브에이전트를 중단하지 않고도 올바른 방향으로 유도할 수 있습니다.

---

## 4. 결론 (Conclusion)
`jeo-code`의 서브에이전트 시스템은 경량성과 안전성을 동시에 만족하는 훌륭한 설계를 갖추고 있습니다. 제안된 개선사항들은 기존의 미니멀 코어 철학(pi-mono)을 훼손하지 않으면서도, 비동기 작업의 사용성과 병렬 실행 효율성을 한 단계 더 끌어올릴 수 있는 실질적인 방안들입니다. 특히 **비동기 상태의 TUI 시각화**와 **파일 수준 잠금을 통한 병렬 변이 허용**은 향후 릴리즈에서 우선적으로 고려할 가치가 있습니다.
