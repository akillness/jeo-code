Generated by deep comparative study of the installed `@gajae-code/*` scoped packages
(`~/.bun/install/global/node_modules/@gajae-code/*`, all at **0.4.3**), the public
`gajae-code` wrapper (`0.2.4`), its `CHANGELOG.md`, and the GitHub repo
`Yeachan-Heo/gajae-code` (workspace version `0.4.4`, README + `docs/codebase-overview.md`

Upstream = **gjc**. Focused pure-TS Bun reimplementation = **jeo-code**.
Everything below is grounded in a named package/crate/file/CHANGELOG entry. Anything not
directly observed is marked `unverified: <why>`.

## 2. PERFORMANCE STORY (native/Rust vs pure JS)

This is the core "perf axis" jeo-code can mine. gjc pushes nearly every hot path into Rust via
N-API; the TS side is glue. Full native surface from `native/index.d.ts` + `native/index.js`.

### Shell execution (biggest perf+correctness win)

- **Vendored brush shell** (`brush-core-vendored` + `brush-builtins-vendored`) is a real Rust
  bash interpreter, exposed through `crates/pi-shell`. Natives: `executeShell(options, onChunk)`
  (streaming one-shot, returns `ShellRunResult`), the persistent `Shell` class
  (`/** Persistent brush-core shell session. */`), and `PtySession` (interactive stdin/stdout
  passthrough) + `Process` (stable process reference with wait/terminate).
- `applyBashFixups(command)` → `BashFixupResult`: conservative AST-based pre-execution command
  rewrites (`crates/pi-shell/src/fixup.rs`).
- **Output minimizer** telemetry (`MinimizerOptions`/`MinimizerResult`) is native — head/tail
  truncation + test-runner noise filtering happen in Rust, not JS.
- Why it matters: no spawning `/bin/bash` per command, deterministic cross-platform shell
  (incl. Windows), in-process streaming, native cancellation.

### Search / file walking

- `grep(options, onMatch)` — ripgrep engine (`grep-*` crates) with native file walking,
  gitignore, context lines, streaming match callback.
- `glob(options, onMatch)` / `find` — glob discovery with gitignore (`ignore`+`globset`).
- `search(content, options)` / `hasMatch(...)` — in-memory regex over buffers/strings.
- `fuzzyFind(options)` — fuzzy path search for autocomplete.
- `listWorkspace(options)` — **single-pass startup workspace scan** returning tree entries +
  AGENTS.md candidates in one walk; backed by an FS scan cache (`invalidateFsScanCache`).

### Code intelligence

- `astGrep(options)` / `astEdit(options)` — ast-grep structural search & rewrite on a Rust
  worker thread (`crates/pi-ast`); supports dry-run, match strictness, meta-vars.
- `summarizeCode(options)` — structural code summary (signatures kept, bodies elided) in Rust.
- `highlightCode(code, lang, colors)` + `supportsLanguage`/`getSupportedLanguages` — syntect
  syntax highlighting → ANSI lines.
- `countTokens(input, encoding)` — tiktoken-rs tokenizer (no JS tokenizer roundtrip).

### Edit hotspots (jsdiff-compatible, native)

- `diffLines(old, new)` — **byte-identical to jsdiff `Diff.diffLines`** but native.
- `h01FindBestFuzzyMatch`, `h02ScoreSequenceFuzzy`, `h06FormatHashLines` — the "hashline"
  edit-anchor fuzzy matching + hash-line formatting hot paths in Rust (these back the
  anchor-based `edit`/`apply_patch` tooling). There is a dedicated `bench:edit-hotspots`.

### Terminal/text measurement (powers the TUI)

- `visibleWidth`, `truncateToWidth`, `sliceWithWidth`, `wrapTextWithAnsi`, `extractSegments` —
  ANSI-aware, tab-aware Unicode width math in Rust (`unicode-width`/`unicode-segmentation`).
- `parseKey`, `parseKittySequence`, `matchesKey`, `matchesKittySequence`,
  `matchesLegacySequence` — Kitty keyboard protocol + legacy escape parsing in Rust.

### Images / clipboard / platform

- `encodeSixel(bytes, w, h)` — SIXEL terminal-image encoding (`icy_sixel`); general image
  decode/resize is delegated to `Bun.Image` on the JS side (deliberately not duplicated).
- `copyToClipboard` / `readImageFromClipboard` (`arboard`).
- macOS: `detectMacOSAppearance`, `MacAppearanceObserver`, `MacOSPowerAssertion` (keep-awake),
  `getWorkProfile` (work profiling), `initNativeCrashDiagnostics`.

### Isolation

- `pi-iso` (`isoResolve/Probe/Start/Stop/Diff`, `IsoBackendKind`) — picks best available
  copy-on-write/overlay backend for writable views over a lower dir (worktree-class isolation).

### Pure-JS (not natived)

Provider HTTP/streaming (`@anthropic-ai/sdk`, `openai`), agent loop & compaction, modes/RPC,
session persistence, web scraping (readability/turndown/linkedom), browser automation
(puppeteer), TUI rendering/layout logic, prompt templating (handlebars), stats dashboard.

**Perf summary for the seed:** gjc's speed comes from (a) a vendored in-process Rust shell,
(b) ripgrep-class search/walk, (c) native ANSI/Unicode text math feeding a differential
renderer, (d) native diff/fuzzy edit hotspots, (e) a single-pass cached workspace scan, and
(f) per-ISA prebuilt binaries (AVX2 modern vs baseline).

## 4. TUI / UX SPECIFICS (code level)

`@gajae-code/tui` is a **pure-TypeScript differential renderer** (package description:
"differential rendering for efficient text-based applications"). It is not a native TUI; it
calls `pi-natives` only for text measurement, highlighting, key parsing, and SIXEL.

### Rendering model (`src/tui.ts`, ~54 KB)

- **Synchronized output**: every render buffer is wrapped in DECSET `\x1b[?2026h` …
  `\x1b[?2026l` ("Begin/End synchronized output") so the terminal swaps frames atomically →
  no tearing/flicker. Cursor positioning is embedded into the same synchronized block.
- **Differential line rendering**: the renderer tracks the previous frame and renders **from
  the first changed line to end** rather than full redraws (`firstChanged`, viewport top/bottom
  math, append-vs-rewrite path). A full-redraw path exists (`recordFullRedraw(reason)`) and is
  metered.
- **Scrollback-aware**: in multiplexer sessions it skips the `3J` scrollback clear
  (`isMultiplexerSession()`) because users navigate scrollback; otherwise `2J/H/3J`.
- **Render metrics**: `metrics.ts` (12 KB) instruments full redraws vs partial; perf gates via
  `PI_TUI_PERF_GATES=1`; debug frames dumpable to `/tmp/tui` via `PI_TUI_DEBUG`.
- **Terminal capabilities**: `terminal-capabilities.ts` (16 KB) + `terminal.ts` (26 KB) detect
  Kitty keyboard protocol, appearance (dark/light via native macOS detection), title/progress,
  synchronized-output support, SIXEL.
- **Input stack**: `stdin-buffer.ts`, `keys.ts` (15 KB), `keybindings.ts`, `bracketed-paste.ts`,
  `kill-ring.ts` (emacs-style), `ttyid.ts`, native Kitty/legacy key parsing.
- **Autocomplete**: `autocomplete.ts` (29 KB) + `fuzzy.ts` backed by native `fuzzyFind`.

### Components (`src/components/`)

`box`, `text`, `truncated-text`, `input`, `editor` (+ top-level `editor-component.ts`),
`markdown` (via `marked`), `image` (SIXEL), `loader` + `cancellable-loader`, `select-list`,
`settings-list`, `tab-bar`, `spacer`. README also documents a container model.

### Theming (`src/modes/theme/defaults/`)

- **Dark default = `red-claw`**, **light default = `blue-crab`** (README "TUI identity"); explicit
  user theme wins. Each is a JSON theme (`red-claw.json`, `blue-crab.json`, ~3.1 KB each) with a
  `vars` palette (named colors like `crabShell`, `claw`, `coral`, `seafoam`, `kelp`, `foam`,
  `deepRed`, `brandRed`, `dangerRed`, `diffRemovalRed`) and a semantic `colors` map
  (`accent→claw`, `border→deepRed`, `borderAccent→brandRed`, message/tool backgrounds, etc.).
  Theme JSON validates against `theme-schema.json`. The crustacean pair (red-claw / blue-crab)
  is the brand identity.
- Status-line is componentized (`src/modes/components/status-line/*`).

## CANDIDATES FOR jeo-code

Pure-TS Bun reimplementation targets. Each tagged `[perf]/[feature]/[ui-ux]/[usability]` and
`[easy]/[medium]/[hard]`, grounded in a named gjc artifact. Difficulty is for a Bun/TS port
(jeo-code stays pure-TS, so "native" perf wins are approximated with Bun primitives, not FFI).

1. **Synchronized-output framing (DECSET 2026)** — wrap every render in `\x1b[?2026h…l`.
   `[ui-ux][easy]` — grounded in `tui/src/tui.ts`. Trivial, eliminates flicker immediately.

2. **Differential line rendering (render-from-first-changed-line)** — track previous frame,
   only repaint changed lines + viewport-aware append path. `[perf][ui-ux][medium]` — grounded
   in `tui/src/tui.ts` `firstChanged`/`recordFullRedraw`. Biggest TUI perf lever without FFI.

3. **Multiplexer-aware scrollback handling** — skip `3J` under tmux/screen.
   `[ui-ux][easy]` — grounded in `tui.ts` `isMultiplexerSession()`.

4. **Bun-native shell instead of per-command spawn** — use `Bun.$`/persistent shell + streaming
   instead of gjc's vendored brush, plus an **output minimizer** (head/tail + test-noise filter)
   in TS. `[perf][feature][medium]` — grounded in `pi-shell` `MinimizerOptions`/`executeShell`.
   Can't match brush in-process bash, but the minimizer + streaming UX is fully portable.

5. **Conservative bash command fixups before exec** — TS rewrite pass for common mistakes.
   `[usability][medium]` — grounded in `applyBashFixups`/`pi-shell/src/fixup.rs`.

6. **Single-pass cached workspace scan at startup** — one walk yielding tree + AGENTS.md
   candidates, with an invalidatable cache. `[perf][usability][medium]` — grounded in
   `listWorkspace`/`invalidateFsScanCache`. Use `Bun.Glob` + a cached FS scan in TS.

7. **ripgrep-class search via Bun** — shell out to `rg` (or Bun glob + streaming) with gitignore,
   context lines, streaming match callback, output mode parity. `[perf][feature][easy]` —
   grounded in `grep`/`GrepOptions`/`GrepOutputMode`.

8. **jsdiff-compatible line diff + hashline fuzzy-anchor edits** — keep gjc's anchor/hash edit
   model in TS using the `diff` package. `[feature][medium]` — grounded in `diffLines` (declared
   byte-identical to jsdiff) + `h01/h02/h06` hashline hotspots.

9. **ast-grep structural search/edit tool** — wrap the `@ast-grep/napi` or CLI for `astGrep`/
   `astEdit` parity (dry-run, strictness, meta-vars). `[feature][medium]` — grounded in
   `astGrep`/`astEdit` + `pi-ast`.

10. **Tokenizer-based context accounting** — `countTokens` parity via `js-tiktoken`/`gpt-tokenizer`
    for accurate budgeting/compaction. `[perf][feature][easy]` — grounded in `countTokens` (tiktoken-rs).

11. **Code structural-summary mode for `read`** — signatures kept, bodies elided.
    `[feature][medium]` — grounded in `summarizeCode`. (jeo-code already does structural summary;
    align the contract/footer with gjc's.)

12. **ANSI/Unicode-aware width, truncate, slice, wrap helpers** — correct CJK/emoji/tab width and
    ANSI-preserving wrap. `[ui-ux][medium]` — grounded in `visibleWidth`/`truncateToWidth`/
    `sliceWithWidth`/`wrapTextWithAnsi`. Use a TS `string-width`/`wcwidth`-class lib.

13. **Kitty keyboard protocol + legacy key parsing** — richer key disambiguation.
    `[ui-ux][medium]` — grounded in `parseKittySequence`/`matchesKey` + `tui/src/keys.ts`.

14. **Crustacean theme identity (red-claw dark / blue-crab light) with appearance auto-detect** —
    JSON theme schema (`vars` palette + semantic `colors`) + OS dark/light detection.
